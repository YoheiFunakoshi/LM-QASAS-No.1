# AbLang2の平均範囲を比較する

この確認は、現行入力を固定した図の比較の第2段階です。特殊トークンを含む現行平均と、CDR-H3残基だけの平均を比べます。**実験用の比較スクリプトであり、通常のアプリの平均方法は変更しません。**

## 何を一つだけ変えるか

AbLang2は入力の各位置について480個の数値を出力します。それらを平均して1配列の表現にする範囲だけを変えます。

| 条件 | 平均する位置 |
| --- | --- |
| 現行：all nonpadding | 開始記号、CDR-H3残基、終了記号、重軽鎖区切り記号。paddingは除外 |
| 比較：residue only | CDR-H3残基のみ。開始・終了・区切り記号を平均から除外 |

モデルへの入力は両条件とも同じです。開始等の記号を入力から削除すると残基の出力自体も変わるため、今回の比較にはしません。同じ推論で取得した最終hidden statesから、2種類の平均を計算します。旧修士論文の「残基平均」という説明が比較の根拠ですが、それだけで共同研究者の実際の実装を確定しません。

現行AbLang2 0.2.1では、重鎖側へCDR-H3、軽鎖側へ空文字列を渡すと、`<CDR-H3>|`となります。残基数をLとした非padding長はL+3です。`rescoding`出力の`[1:1+L]`を残基として切り出します。現行公式`seqcoding`と同じ計算精度にするため、平均前にfloat64へそろえます。人工入力の公式API照合、全配列の旧cache照合、平均の恒等式で位置と計算を確認します。[実装の確認記録](ABLANG2_NOTES.md)

## 固定するもの

- Dを採否に使わない現行入力、read数1の採用、V/J/CDR-H3/isotypeのclone定義。
- 採用配列・全clone観測・並び順。同じCDR-H3を持つ別cloneや別時点の観測を統合しない。
- モデルと重み、CPU、batch size、thread、入力整形、出力層、dtype。
- UMAPの距離・近傍数・min_dist等。各fitでは3時点の全cloneをまとめて計算する。
- KDEのGaussian kernelと等重み、帯域幅の数値、格子、各時点の積分1、表示色尺度。

Top Nはこの比較に使いません。背景は採用済みの全cloneです。候補の再選択と赤点の照合は行いません。

## 乱数による変動を分けて見る

現行seedと、事前指定した別seedの2つを、両平均方法に共通で使います。既定は20260919と20260920です。これは元論文のseedを推定した値ではありません。

| | 現行seed | 追加seed |
| --- | --- | --- |
| 特殊トークン込み平均 | A0 | A1 |
| 残基のみ平均 | B0 | B1 |

A0とB0、A1とB1は平均範囲の比較です。A0とA1、B0とB1は乱数への感度確認です。2seedで広い意味での安定性を保証しません。[UMAP公式の再現性説明](https://umap-learn.readthedocs.io/en/latest/reproducibility.html)

再計算した現行embeddingが保存済みcacheと全成分で完全一致し、入力対応・設定・環境・保存hashが一致した場合のみ、A0の保存済み座標を再利用します。それ以外は現行方式も同じ手順で再計算し、差を記録します。

## 比較図を読む

独立したUMAPの上下左右はそのまま比較できません。clone行の対応を使い、基準の現行図へ平行移動・回転・鏡映のみで向きをそろえます。拡大縮小や論文画像への形状合わせはしません。元座標、向き合わせ後の座標、変換行列を保存します。

KDE帯域幅は保存済み現行図の値に固定し、4条件を覆う共通格子を作ります。すべての時点・条件で同じ色尺度、等アスペクトを使います。比較用に格子を広げたため、現行図も同じ座標からKDEを再評価します。画像を無加工で再掲したものとは区別します。色は時点内の分布を示し、clone総数の違いは示しません。

- `pooling_paper_comparison.png`：論文参照、現行方式、残基のみ方式。論文の座標・密度尺度は別です。
- `pooling_seed_comparison.png`：2方式×2seedの背景図。どの条件も全cloneを保持します。

論文参照画像はそのまま使い、元画像内の赤点を今回の評価に含めません。

## 見た目以外の確認

全配列で、同じCDR-H3の2表現間のcosine距離と相対L2変化を確認します。さらに、長さと保存順から事前に決めた標本について、配列ペアのcosine距離の順位相関と、近い15配列の共通率を計算します。近傍検索の相手は全ての異なるCDR-H3で、自己は除外し、同距離は保存index順とします。

この診断だけはCDR-H3単位です。UMAPの点をCDR-H3単位に減らす処理ではありません。最大1,024配列のペア距離、最大512配列のqueryという標本診断を、全queryを調べた結果とは呼びません。2次元では時点別に固定したclone標本の点間距離順位と、全cloneの剛体整列後RMS変位を確認します。

先方のUMAP座標がないため、論文への定量的な類似度や厳密再現の成功判定は行えません。目視の特徴、数値表現の変化、乱数変動、未確定の元条件を分けて説明します。

## 再実行

プロジェクト直下で、確認済みのD不使用runと、そのrunに属するprojectionを指定します。以下のパスは説明用の置き換え箇所です。

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONDONTWRITEBYTECODE='1'
.\.venv\Scripts\python.exe scripts\compute_pooling_comparison.py --run-dir "<saved_run>" --projection-dir "<saved_projection>" --model-dir models\ABLANG-2-paired --output-dir "<new_comparison_folder>"
.\.venv\Scripts\python.exe scripts\render_pooling_comparison.py --comparison-dir "<new_comparison_folder>" --reference-image "<local_reference_image.png>"
```

比較先は元入力・資料・モデル・既存runの外に新規作成します。既存ファイルを上書きしません。`--stage embeddings`で推論のみ、`--stage projections`で保存済みの2種類のembeddingから後段を実行できます。UMAPの途中停止は完了したfitの設定・hashを検査して再利用します。整列・KDE以降で停止した場合は、残存ファイルへの上書きを拒否するため、自動再開が保証されるものではありません。

`embedding_metadata.json`に平均定義とcache照合、`comparison_metadata.json`に入力・設定・標本診断・由来、`render_metadata.json`に図の表示条件を保存します。実配列、個別件数、画像、hash、独立監査はローカルに保持します。GitHubには汎用コード、人工テスト、方法と判断の記録だけを置きます。

## 今回の検証と判断

2026-09-20に全配列で2種類の平均を計算し、全cloneを保持した2方式×2seedの背景比較を完了しました。再計算した現行平均は保存cacheと全成分で完全一致しました。比較図2枚を描画して目視確認し、入力・元結果・モデルのhash、全clone対応、剛体変換、近傍診断を独立に照合しました。人工データの8テストも成功しました。

KDEの独立監査では、ゼロに近い尾部の一部で相対誤差だけの基準を満たしませんでした。初回の失敗記録を保持し、原因を確定したとは扱いません。全体の表示精度を評価するため、相対許容にパネル最大密度の1e-12という絶対誤差床を加えた検査を別途行いました。確認した標本格子点では作図への影響は小さい範囲でした。全格子の厳密な相対精度を検証したという意味ではなく、計算結果と図は変更していません。詳細は非公開監査に残します。

現行から残基のみの平均へ変更する十分な根拠は、この比較では得られていません。論文への厳密な一致や候補抽出性能の向上を実証したものでもありません。標準の平均方法は維持し、先方の回答を待ちます。次の検討候補は、現行embeddingを固定したUMAP設定の比較です。個別の数値と図はローカル結果に保存し、この公開文書には転載しません。
