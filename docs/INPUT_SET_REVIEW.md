# 第1段階：背景図へ入れるクローン集合の確認

確認日：2026-09-20。Dを採否に使わない現在の運用を起点に、論文 Fig. 1c と背景図が違う理由を順に確認する。今回は入力集合だけを点検する。論文を比較のお手本とするが、見た目を似せるためだけの条件変更は行わない。赤点の検討は後の段階とする。

## 1. 「全件」の意味

背景図の全件とは、**採用条件を満たし、各時点でクローンを整理した後の全件**である。元Excelの全行、重複しないCDR-H3の種類数、出力候補数はそれぞれ異なる。

```text
Back_data!G:Q の全行
    ↓ 読み枠、V/J、CDR-H3、C注釈の採用条件
採用した元行
    ↓ 各時点で V / J / CDR-H3 / isotype が同じものをまとめる
各時点のクローン
    ↓ 各クローンに対応するembeddingを並べる
全クローンを共通UMAPへ渡し、時点別の背景密度を計算
```

同じCDR-H3のembeddingは計算を再利用するが、V/J/isotypeや時点の異なるクローン観測は残す。Top Nの指定は背景へ渡す件数を制限しない。元Excelの上位50件のランキングも入力には使わない。

## 2. 論文の記載と現在の処理

| 確認項目 | 論文の根拠 | 現在の処理と判定 |
| --- | --- | --- |
| 背景の対象 | Results 2.2は3時点の全BCR配列を可視化すると説明 | 採用後の全クローンを使用。上位候補だけに限定しない方針は整合 |
| クローンの単位 | Methods 5.4のV/J/CDR-H3/isotype | 同じ4項目を使用。正規化の細部は下表のとおり未確認 |
| 点の重み | Methods 5.4は各クローンを1点とし、read数を使用しない | クローンを等重みで使用。read数による複製・重み付けはしない |
| モデルへの入力 | Methods 5.4はCDR-H3のみ | CDR-H3のみ。全長VDJやV/J名をモデルへ入力しない |
| 採用条件 | Methods 5.3の読み枠・stop・機能性・長さ | V/Jの供給注釈、in-frame、標準20アミノ酸、長さ5以上等を検査。全VDJの独立した機能性検証ではない |
| Dの扱い | Methods 5.3にはfunctional Dの記載あり | 利用者の承認どおりDは採否・クローン定義に不使用。元解析のD処理が判明したという意味ではない |

出典：[最新論文のResults 2.2・Methods 5.3–5.4](https://www.frontiersin.org/journals/immunology/articles/10.3389/fimmu.2026.1844788/full)。本文の「全配列」は、前処理の記載と合わせて読む。最終入力表がないため、論文図と現在の入力集合の完全一致は確認できない。

## 3. 入力集合を変え得る未確認事項

| 項目 | 現在の処理 | 原法について未確認の点・確認の考え方 |
| --- | --- | --- |
| isotypeの粒度 | IgG1〜4などのsubclassを保持 | 論文のisotypeがどの粒度か、元コードは未入手。classへまとめる仮集計では、CDR-H3種類数とクローン数を別々に比較する |
| 曖昧なC注釈 | 単一subclassへ決まらない行は除外 | subclass保持と別の論点。classに決まるという理由で自動採用せず、他条件を満たす除外行を別集計する |
| 対象の抗体class | 注釈された対応済みC/isotypeを使用し、ファイル名だけでIgGに限定しない | Methods 5.2のIgG特異的プライマーの記載だけでは、異なるclassの注釈を元解析が除外したかは分からない。自動的に誤注釈・混入と断定しない |
| 複数のV/J候補 | alleleを外した候補集合を保持 | 先頭候補の選択、曖昧行の除外などを元コードがしたか不明。どちらも情報を捨てるため、見た目だけを理由に導入しない |
| allele | V/J/Cのallele表記を外す | 論文のgeneという単位を参考にした実装。具体的な文字列処理との一致は未確認 |
| CDR-H3の境界 | 元のアミノ酸配列をそのまま使用 | 末端文字の分布を調べても、境界定義の正しさや原法の処理は確定しない。C/Wの付加・削除はしない |
| 最低read数 | read数2以上という追加条件はなし | 旧修士論文の条件と最新本文を区別する。最新本文は最低read数を明記していない。元行の除外とクローン集計後の除外を別に仮集計する |

read数を重みにしないことと、少数readを除く条件がないことは別である。旧修士論文の最低read数条件はPDF39ページ・本文28ページの4.2節で再確認した。同様に、クローン数が変わることと、異なるCDR-H3の集合が変わることも区別する。仮集計は入力の感度を見るもので、論文設定や図の違いの主因を確定するものではない。

## 4. 今回の検証範囲

原Excelを独立に読み、現在の保存runについて次を照合した。実配列・個別件数・検体情報・hash・詳細な比較表は、Git管理外の `local_records/input_set_review_20260920/` に保存する。

- 原本と保存成果物のhash、入力policyと時点の対応。
- 元行数、採用・除外行数、4項目でまとめたクローンと元行への対応。
- 異なるCDR-H3とembedding indexの対応、全クローンと座標行の対応。
- 全クローンを使用し、downsamplingやCDR-H3単位の観測点統合をしていないこと。
- 上記の未確認項目による件数の感度。現在の条件から一項目ずつ変える比較と、class統合後に曖昧Cの採否を変える段階的比較を区別すること。後者の最終集合と現行との直接比較は二つの変更を含む。

独立照合は43項目すべて成功した。今回の変更は文書のみで、アプリの全テストを再実行したという意味ではない。

入力・解析コード、採用条件、モデル、座標、密度、元画像は変更していない。AbLang2の再推論、UMAP/KDEの再計算、候補選択の再実行は今回の範囲外である。

## 5. この段階の結論と次の確認

**現在の図が上位1,000種類だけを背景にしている、という問題ではない。** 全採用クローンを等重みで扱う基本方針は論文の記載に整合する。ただし原法の最終入力表がなく、入力集合が完全に同じかは未確認である。

未確認の入力条件を見た目だけで変更せず、現在の入力集合を固定した基準として保持する。次はCDR-H3からembeddingを作る処理を確認し、その後にUMAP、KDEを一つずつ調べる。別条件を試す場合は、根拠・変更箇所・比較する量を先に定め、新しい保存先で比較する。
