# 論文図の再現探索を止める条件・再開する条件

2026-09-20。利用者から、追加試行を続ける価値と回答を待つ価値を再評価する依頼を受けた。本書は方法と進め方の記録であり、実データの数値・図・個別監査結果は含まない。

**原図の作成条件を照合できない間は、外形の類似だけを目的にした追加パラメータ探索を一旦停止する。アプリの動作・候補抽出の検証は、図の再現とは別の課題として扱う。**

## 1. 判断する対象を分ける

| 目的 | 判断に使えるもの | それだけでは判断できないもの |
| --- | --- | --- |
| 原図を同じ方法で再現する | 元の入力表、モデルと表現、前処理、座標、作図コードとの段階別照合 | 画像の輪郭が似ていること |
| 当方の可視化条件を設定する | 条件の記録、同一条件での再実行、近傍関係の保持、乱数による変化 | 論文と同じ条件であること、候補の抗原特異性 |
| 有用な配列を抽出する | 高次元空間のスコアと時系列、候補の安定性、将来の独立した生物学的評価 | UMAPの形、図の山の美しさ、処理の完走 |

論文Results 2.2ではUMAPを可視化に使い、候補抽出に関する密度評価は高次元embedding空間で行うと説明されている。したがって、表示条件を合わせることと候補抽出性能を検証することを同じ達成条件にしない。[論文全文](https://www.frontiersin.org/journals/immunology/articles/10.3389/fimmu.2026.1844788/full)

図が一致しないだけで当方の解析の誤りは確定しない。一方、不一致があるから入力や実装を点検しなくてよいわけでもない。現行値は追跡可能な暫定基準として保持し、最適値・論文設定と呼ばない。

## 2. 追加比較の判断規則

追加実験の前に「何が違うという根拠があるか」「どの条件を固定するか」「どの観測なら判断が変わるか」を文章で決める。

- 新たな根拠がなく、採否の基準が見た目の類似だけなら実行しない。
- 元コード・保存された中間結果・公開資料から具体的な相違を確認できたら、その相違だけを調べる限定比較を設計する。
- 実装の不具合が見つかった場合は、論文の返信を待たずに修正・検証する。
- 有限の条件・少数のseedを比較した結果から、未試行の条件や組合せを原因から除外しない。
- 原図の座標がない間は「論文再現率」を付けない。高次元と2次元の近傍一致は別の診断指標である。

これまで用意した比較方法は、[pooling](POOLING_REVIEW.md)、[近傍数](UMAP_NEIGHBORS_REVIEW.md)、[min_dist](UMAP_MINDIST_REVIEW.md)、[KDE帯域幅](KDE_BANDWIDTH_REVIEW.md)、[初期配置・距離尺度](UMAP_INIT_METRIC_REVIEW.md)、[最適化回数](UMAP_EPOCHS_REVIEW.md)から参照できる。実際の成果物に基づく総括はGit管理外のローカル記録に保存する。

## 3. 残る候補を自動的に試さない理由

PCA、別のKDE実装、UMAPへ渡す集合やモデル条件など、未照合の事項は残る。ただし、未試行という理由だけでは次の実験の優先根拠にならない。

PCAは前処理の候補だが、原図で使われたと確認されていない。scikit-learnのPCAは入力を中心化してから変換する。[公式仕様](https://scikit-learn.org/stable/modules/generated/sklearn.decomposition.PCA.html)。中心化はcosine距離を変え得るため、今後比較するときは、次元削減の効果と中心化の効果を分ける必要がある。保持分散だけでは局所近傍や生物学的情報の保持を保証できない。

**PCAを次に自動実行する方針は保留する。** 以前の記録にある「次の候補」は実施済み・採用済みという意味ではなく、本書の再開条件を適用する。

## 4. 共同研究者から優先して照合するもの

既存の[確認表](COLLABORATOR_QUESTIONS.md)を繰り返し増やすより、次の2組を優先する。共有は適切な非公開経路で行い、公開GitHubへ置かない。

1. **作図に実際に用いた最終入力表**：時点・対応ID・元行または配列・cloneの定義が分かるもの。件数だけの一致は集合の一致を意味しない。確認表1・2・9番に対応する。
2. **同じ対応IDのembedding・UMAP座標、または作図Notebookと設定・環境情報**：入力 → 数値表現 → 配置 → 密度表示の順に照合し、最初に差が生じる段階を特定する。確認表6〜13番に対応する。

全てを一度に受領できなくても、座標と点・時点の対応があればKDEと描画の照合を先行できる。座標だけでモデルや入力の一致まで証明することはできない。

## 5. 回答待ちと独立に進められること

次の課題はアプリ品質の検討候補であり、本書作成時に新たに実測したものではない。

- 候補抽出の乱数を変えたとき、Top Nに共通するCDR-H3と入れ替わるCDR-H3を調べ、スコアの同点・出力境界も区別する。
- 同一条件での再実行と、候補 → スコア → 時点別clone → 元行の追跡を確認する。
- 図を再作成する操作と候補を再計算する操作を、説明書・画面で明確に伝える。

安定した候補が必ず抗原特異的であるとは限らない。抽出の安定性、実装の正確さ、生物学的妥当性は別々に評価する。原図の再現を再開する際も、入力条件変更や赤点の検討はこれまでの保留方針を維持し、対応する根拠を確認してから扱う。
