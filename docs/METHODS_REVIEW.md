# 論文Methodsと現行実装の照合

確認日：2026-09-20。最新論文のMaterials and Methods 5.2–5.5、Results 2.1–2.2、Fig. 1cと、現行ソース・保存済み実行条件を照合した。**背景図の違いを説明する最優先の確認事項は、前処理後の入力集合と、UMAP/KDEの条件である。** 未記載の値は元法との差が確定したものではなく、照合すべき条件として扱う。

この公開文書には一般的な方法の対応だけを記載する。実配列・検体情報・個別集計・hash・監査詳細は `local_records/` に保存する。

更新：利用者の明示承認により、Excelの新規解析はDを採否に使わない `takara-rg-hIGH20181210-v2-ignore-d` を採用する。[入力規則と理由](TAKARA_INPUT.md)。D検査を行う旧policyとの[背景比較](D_FILTER_COMPARISON.md)と、本番の新規解析を区別する。旧runを新policyで計算済みとは扱わない。

## 2. 入力集合の照合を最初に行う理由

旧Excel policy v1はV/D/Jそれぞれの機能ラベル `F` と有効な注釈を求めた。D注釈と機能が `x` の行には両方の除外理由が付いた。理由件数には重複があるため、足し合わせて除外行数にはしない。新policy v2-ignore-dはV/Jなど他の条件を維持し、Dの2条件を採否から外す。

旧条件は論文の「functional Dを使用」という文章に沿う解釈だったが、レポートの `x` を元コードがどう扱ったかは未確認である。`x` をORFやpseudogeneと同義にしない。今回の変更はD割当の不確実性と利用者の承認に基づく運用判断であり、論文の元解析条件が判明したという意味ではない。

D不使用を承認済みの起点として、各時点の最終clone数 → 採用行とclone表 → V/J曖昧候補・isotype/subclass・配列境界・最低read数の順に確認する。同じ検体名だけでは、UMAPへ渡した点の集合が同じとは限らない。[第1段階の確認記録](INPUT_SET_REVIEW.md)に、全採用クローンの保持と残る未確認事項をまとめた。

別の定義でclone数を集計する感度確認は、原法の再現と区別する。例えばsubclassをIgGへまとめると同じ配列の観測点数が減り得る一方、CDR-H3集合自体は変わらない場合がある。前処理の影響は点数だけでなく、長さ分布や時点間の共有にも及ぶ。

## 3. UMAPの条件は論文のk-NN条件と別

**5.5.2–5.5.3のcosine距離とk=200は、480次元で候補スコアを求めるk-NN法の条件である。UMAPのmetricやn_neighborsの指定ではない。** これをUMAPの論文設定として転用しない。

現行のUMAPは次の暫定条件を使う。共同研究者の設定を復元したものではない。

| 項目 | 現行の値 | 図への関係 |
| --- | --- | --- |
| metric | cosine | 高次元で何を近いとするか |
| n_neighbors | 15 | 局所構造と大域構造の重視の程度 |
| min_dist | 0.1 | 2次元で点を密集させる程度 |
| init | random | 計算開始時の座標配置 |
| n_epochs | 200 | 座標最適化の反復数 |
| random_state | 20260919 | 同条件での追跡用に固定した乱数 |
| unique | false | UMAP入力の同一ベクトル行を重複除去しない |

近傍数やmin_dist、距離の選択は図の形に影響する。[UMAP公式パラメーター解説](https://umap-learn.readthedocs.io/en/latest/parameters.html)。乱数や実行環境の条件も合わせる必要がある。[公式の再現性説明](https://umap-learn.readthedocs.io/en/latest/reproducibility.html)。単に画像の外形へ似せる目的で設定を探索しても、元解析の再現成功とはならない。

## 4. KDE・AbLang2にも未確認事項がある

KDEは点の分布を滑らかな色の山として表す。現行はGaussian kernel、3時点共通の等方的帯域幅、96×96共通格子、各時点の有限格子上の積分1を使用する。帯域幅は全観測の2軸分散と点数から計算する。論文本文はKDEと記載するが、帯域幅・カーネル・格子・正規化の具体値は示していない。帯域幅は島のつながりや山の見え方に関係する。

ただし、固定された密度格子へ時点ごとの定数を掛ける最後の積分補正は、点を動かしたり、時点内の密度順位を変えたりしない。帯域幅の効果と混同しない。

AbLang2はCDR-H3のみを使う点が一致していても、版・checkpoint・poolingが同じかを確認する必要がある。現行は0.2.1の公式seqcodingで、CDR3に加えて開始・終了・重軽鎖区切りの3特殊トークンを平均に含む。これは残基だけの平均とは異なる。最新論文には厳密なpoolingがない。旧修士論文は残基平均と説明するが、特殊トークンの扱いを確定できるコードはない。[AbLang2設定の記録](ABLANG2_NOTES.md)

同じモデル入力に対して平均する範囲だけを変える限定的な感度確認は実施したが、これで共同研究者のpoolingが判明したわけではない。UMAPを含む全解析の再実行ではなく、主因を特定した試験でもない。

## 5. 背景図の原因と混同しない項目

- **K=500、ε、Top N**：現行では候補選択に作用する。背景は全採用cloneのembeddingから作るため、これらの値を変えても保存済み背景の形は直接変わらない。
- **k-NN未実装**：論文にはK-means版とk-NN版の両方があるが、UMAPの背景はその二者のclusterラベルを描いたものではない。
- **read重み付け**：最新5.4は明確に不使用。背景が違うからとread重みに変更する根拠はない。
- **read数2以上**：旧修士論文にある条件。最新論文本文は最低read数を明記していない。重み付けの不使用と最低read数filterは別問題なので、元コードで要確認。
- **CDR-H3だけで観測点を一意化**：出力のTop Nの数え方と、論文の解析用cloneの単位を混同しない。

最初のMethods照合時は原文・実装・保存条件の確認と限定的な感度集計で、アプリの既定値を変更していなかった。その後、背景図の比較と、利用者承認によるDを採否に使わない新policyへの変更を別段階として記録した。元法の再現条件を確定する順序は引き続き「入力clone集合 → embedding → UMAP座標 → KDE → DB由来の印」とする。
