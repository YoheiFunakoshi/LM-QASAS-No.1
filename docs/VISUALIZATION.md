# 共通UMAP図とローカル操作画面の解説

この文書は、Pre・Peak・Postの比較図で何を見ているか、表示した候補とCSVがどう対応するかを説明します。起動・ファイル選択の手順は[日本語解説書の6節](GUIDE_JA.md#6-実行と出力数だけを変える操作)、実装と検証の状態は[開発記録](DEVELOPMENT_LOG.md)を参照してください。

人工データの対応・正規化・再利用テストに加え、保存済み実データrunで共通UMAP図の作成、候補数変更、CSV/PNG取得を確認しました。GUIからの新規解析は人工3CSVでAbLang2から画像作成まで検証しています。詳細な範囲と結果は開発記録を参照してください。

## 1. スコアを決める処理と、図を描く処理

AbLang2で得た480次元embeddingを使う処理には、別々の目的があります。

```text
Pre / Peak / Postのclone観測と480次元embedding
    ├─ K-means → clusterスコア → Peakの候補 → 異なるCDR-H3をTop N選択
    └─ 共通UMAP → 2次元の座標 → 時点別の背景密度と候補の印
```

**順位は480次元で行うK-means解析の結果で決まります。** UMAPの座標や背景の色を候補スコアへ戻す処理はありません。UMAPの表示条件を変えたとしても、それ自体でK-meansのスコアが変わるわけではありません。

UMAPは高次元の関係を2次元へ表す手段ですが、元の密度をそのまま保存する方法ではありません。島の間の距離、島の大きさ、色の濃さだけで抗原結合能や480次元空間の密度を判断しません。[UMAP公式FAQ](https://umap-learn.readthedocs.io/en/latest/faq.html)

## 2. 3枚で共通にするもの

Preだけ、Peakだけ、Postだけを別々にUMAP計算すると、それぞれ異なる座標ができます。今回の実装では、**3時点のclone観測をすべてまとめて1回だけUMAPを計算**し、その共通座標を時点別に表示します。

| 図の要素 | 3時点でそろえる条件 | 読むときの意味 |
| --- | --- | --- |
| 横軸・縦軸 | 同じ座標系と表示範囲 | 同じ図の位置を時点間で比較できる |
| 背景の平滑化 | 同じ帯域幅と格子 | 1枚だけ強くならした表示にしない |
| 色 | 同じカラースケール | 同じ色は同じ2次元密度値に対応する |
| 候補の判定 | Peakで選んだCDR-H3の集合 | 3枚で別々に候補を選ぶわけではない |

点の単位は各時点のunique cloneです。同じCDR-H3でもV/J/isotypeが違えば別の点として解析に含め、同じcloneが3時点にあれば各時点の観測を保持します。Countsによる点の複製や重み付けは行いません。配列のembedding計算を再利用することと、clone観測を1点へ統合することは別です。

UMAPはrunごとに作ります。同じ座標系という保証は、そのrunの3時点の間でのものです。別の人、別の入力、別の条件で作ったrunの図を、座標が一致するものとして重ねてはいけません。

## 3. 背景色は何を表すか

背景は、2次元UMAP上のcloneの位置をGaussian KDEでならした密度です。KDEは、各点の周りに滑らかな山を置き、それらを重ねて分布を見る方法です。今回の表示では各cloneを等重みとして各時点の総数で割った密度を求め、さらに**共通の表示範囲で積分が1になるように正規化**します。画面端より外の小さな裾と格子近似の影響をそろえるためです。

このため、明るい部分は「その時点の分布の中で、この付近に点が集まっている」ことを示します。PreよりPeakの全clone数が多いこと自体を、背景の全面的な明るさで示す図ではありません。clone総数、選択CDR-H3と一致するclone数、候補CDR-H3の種類数は、それぞれ別の数値として確認します。

たとえば、架空の例として時点Aに100 clone、時点Bに1,000 cloneがあり、同じ形の分布なら、正規化した背景密度もほぼ同じ形・明るさになります。この図から時点Bのclone数が10倍だとは読み取れません。この例は図の意味を説明するためのもので、提供データの集計ではありません。

図中のKDEは表示のための2次元密度です。古い修士論文のKDEスコアを今回の候補抽出へ追加したものではありません。

## 4. 候補の印と件数

濃い縁の付いたオレンジ色の印は、**今回Peakで選んだCDR-H3と同じ配列を持つclone観測**を示します。凡例の`Peak-selected CDR-H3 occurrences`はこの意味です。Peakで選ぶ候補はTop N種類ですが、図上の点はclone単位なので、同じCDR-H3が複数のcloneに対応すれば複数点へ印が付きます。点が重なる場合もあり、見た目の印の数だけを数えて候補種類数を確認することはできません。

PreやPostに印がある場合、その時点にも選択CDR-H3と同じ配列が存在します。V/J/isotypeの組合せまで同一であるとは限りません。Peakにない配列をPre/Postから新たに選ぶ処理ではありません。

| 表示・記録する数 | 数える単位と分母 |
| --- | --- |
| 指定数 | 利用者が希望したCDR-H3種類数 |
| 出力数 | 実際に選んだ重複しないCDR-H3種類数 |
| 各時点のclone数 | その時点の解析対象clone観測の総数 |
| 選択配列と一致するclone数 | その時点で、選択したCDR-H3集合に一致するclone観測数 |
| 一致cloneの割合を示す場合 | 一致clone数 ÷ その時点のclone総数 |

Top Nの境界で同点があれば、辞書順で区切ったことと同点の情報を確認します。図上の位置によって同点内の順位を決めているわけではありません。候補不足は不足数として表示し、同じ配列を複製して指定数へ水増ししません。

印は既知抗体DBとの照合結果ではありません。論文図で使われる「既知DBに関連する配列」の赤点とも意味が異なります。また、抗原特異性・結合能・中和能が実験で確認されたことを示す印でもありません。

## 5. 今回のUMAP条件と、その位置付け

次は今回の可視化に採用する暫定設定です。元論文の厳密な設定がすべて確認できたという意味ではありません。

| 設定 | 今回の値 | 用途・理由 |
| --- | --- | --- |
| 入力 | 全3時点のclone観測に対応する480次元embedding | cloneの単位と時点の由来を維持 |
| n_components | 2 | 人が比較図を見るため |
| metric | cosine | embeddingの方向に基づく距離を可視化で使用 |
| n_neighbors | 15 | 局所関係を見る範囲の暫定値 |
| min_dist | 0.1 | 2次元での点の集まり方を調整する暫定値 |
| random_state | 20260919 | 同じ条件で比較しやすくするため |
| n_jobs | 1 | 実行条件を固定して記録するため |
| n_epochs | 200 | 計算量を明示するための暫定値 |
| low_memory | true | 近傍計算のメモリ消費を抑えるため |
| init / spread | random / 1.0 | 初期化と2次元での広がりを固定して記録 |
| 入力の数値型 | float32 | UMAP計算用。保存済みAbLang2 embeddingを上書きしない |
| unique / densmap | false / false | clone観測の重複除去やdensMAPへ切り替えない |
| 近似近傍計算の強制 | clone観測数が4,096を超える場合 | 大規模入力の計算方法を明示 |

n_neighborsやmin_distは図の形に影響します。[UMAP公式パラメーター解説](https://umap-learn.readthedocs.io/en/latest/parameters.html)は値の役割を説明する資料であり、LM-QASAS論文の未記載値を確定する資料ではありません。cosineはここでのUMAPの条件です。今回のK-meansをcosine K-meansへ変更したという意味ではありません。

seedを指定していても、ライブラリ版・OS・実装・入力順が変わった場合まで座標の完全一致を保証するものではありません。比較時は保存済み座標と条件を使います。初回はNumbaのJITコンパイルで追加の待ち時間が生じることがあります。[UMAP公式の再現性の解説](https://umap-learn.readthedocs.io/en/latest/reproducibility.html)

観測数が4未満、またはn_neighborsが観測数以上の場合は停止します。小さい入力に合わせて値を黙って変更しません。また、cosine距離を定義できないゼロベクトルや、密度表示に使えない退化した座標もエラーとして扱います。

背景密度の条件も暫定設定として保存します。格子は96×96、帯域幅は全時点をまとめた座標から`sqrt(mean(軸ごとの標本分散)) × n^(-1/6)`で1つ決め、3時点に共通で使います。nは全clone観測数です。表示余白は各軸の`max(帯域幅の3倍, 座標幅の5%)`です。Gaussian KDEをball treeで計算し、相対許容誤差を`1e-6`、絶対許容誤差を0にしています。有限格子上の積分は台形則で求めます。これらは背景図の作成条件であり、K-meansのcluster数や候補スコアの条件ではありません。

## 6. 件数変更で計算し直すもの

| 操作 | AbLang2・K-means | 共通UMAP・背景 | 候補選択・印 |
| --- | --- | --- | --- |
| 新しい3ファイルで解析 | 計算する | 作成する | 指定数で作成する |
| 完了済みrunを開き「共通UMAPを作る」を押す | 保存済みを読む | 未作成なら作成する | 保存済み候補を表示する |
| 同じrunでTop Nだけを変える | 再計算しない | 同じ座標・背景を再利用 | 保存済みスコアから再選択する |
| 保存済み選択結果を開く | 再計算しない | 保存済みを再利用 | その選択結果を表示する |

候補数を変えた比較では、図の地形が固定され、選択に対応する印が変わります。座標・背景と、候補選択ごとの画像を別に保存するためです。新しい選択結果は以前の結果を上書きしません。

入力、filter、pooling、モデル、K、εなどを変える場合は新しい解析です。Top Nの切替として扱わず、別runを作ります。改変された保存ファイルの検査に失敗した場合も、表示を取り繕って続行せずエラーとして扱います。

## 7. このPCでの動作と記録

画面のサーバーは`127.0.0.1:8765`で待ち受けます。解析結果をインターネットへ公開する仕組みではなく、このPCのブラウザーから操作するためのものです。GUIから選んだCSVは`local_records/ui_inputs/`へ解析用コピーを作り、結果は`outputs/`に保存します。元データの削除・改変は行いません。

画像、候補、コピーしたCSV、座標・密度のキャッシュは研究データとしてローカルに保持します。公開GitHubにはコード・模擬テスト・操作方法・判断理由・検証範囲を記録します。実データの図を解説書の例として無断で掲載しません。

候補CSVやPNGを保存したときは、同じrun・同じ選択結果から取得したことが分かるように保管します。画像だけで解析条件や入力監査の情報をすべて代用できるわけではありません。後日振り返るときはrunの実行記録、入力監査、候補選択の集計、図の設定を一緒に確認してください。

### 保存フォルダーと検査対象

共通座標と背景を`outputs/run_.../projection_日時_ID/`へ保存し、その中に選択結果ごとの`view_日時_ID/`を作ります。

| ファイル | 意味 |
| --- | --- |
| `projection_.../coordinates.npy` | `clones.json`と同じ順序の2次元座標 |
| `projection_.../density_grid.npz` | 共通の横軸・縦軸格子と3時点の密度 |
| `projection_.../projection_metadata.json` | UMAP/KDEの条件、元runとの対応、ライブラリ版、コード・成果物のhash、実行状態 |
| `projection_.../view_.../comparison.png` | 3時点の比較図。選んだ候補の印を重ねたPNG |
| `projection_.../view_.../view_metadata.json` | 参照するrun・座標・候補選択、強調したcloneの対応、色・軸、成果物hash |

可視化では完了済みrunだけを対象にし、embedding・配列index・clone・Peakスコアの保存時hashを照合します。処理前後で元runのmetadataを含めて変化がないことを検査します。画像を描くときは座標・背景も照合し、候補CSV・由来・集計が検証済みスコアから再計算した選択と一致するかを確認します。これは改変や取り違えを検出するための検査であり、元のスコアが生物学的に正しいことを証明する検査ではありません。

起動中のブラウザーを閉じても、サーバーや解析が終了するわけではありません。終了するときは処理の完了を確認してから、起動ウィンドウでCtrl+Cを押します。サーバーを途中で終了しても実行中の解析プロセスが残る場合があるため、処理中にサーバーを終了して同じ解析を再投入する操作は避けます。終了操作で入力コピーや結果を削除する機能はありません。

## 8. 困ったとき

| 状況 | 確認すること |
| --- | --- |
| 画面が開かない | 起動ウィンドウのエラー、表示URL、専用環境の準備状態 |
| 起動時にポート・二重起動のエラーが出る | すでに同じアプリを起動していないか確認。同じプロジェクトは別ポートでも同時に2つ起動できない。起動済みURLを開くか、完了後に既存サーバーを終了する |
| CSVのサイズ上限に達した | 1ファイル20 MiB、3ファイルの送信形式全体64 MiB（元CSV合計は約48 MiB未満）を確認。大きい入力にはCLIを使う |
| UMAP段階で待ち時間が長い | 初回JITや入力規模の影響を考え、表示された処理段階と起動ログを確認 |
| 指定Nより出力が少ない | 入力監査と利用可能なCDR-H3種類数、不足数を確認 |
| 候補表と図の件数が違って見える | 表はCDR-H3種類、図はclone観測で、点の重なりもあることを確認 |
| Kが大きすぎるというエラー | 観測数と異なるembedding数を確認。理由を記録してKを変更し、別runで実行 |
| ファイル検査でエラーになる | 原本・保存結果を直接書き換えず、問題のrunと検査段階を記録して確認 |

k-NN版、GPUでの高速化、複数人の統合、抗原特異性の性能評価は今回の可視化・画面追加とは別です。各段階の完了を[開発記録](DEVELOPMENT_LOG.md)で区別します。
