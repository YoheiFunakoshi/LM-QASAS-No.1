# 開発計画

2026-09-19 更新。目標は、1人分のPre・Peak・Postを読み込み、解析の状況と画像を見ながら指定数の候補を抽出できるアプリです。

## 今回の区切り

環境構築と人工配列10本によるAbLang2最小検証を完了しました。実データのembedding、候補抽出、GUIはこれからです。段階ごとに結果と次の判断をユーザーへ共有します。

## 開発の順序と完了条件

| 段階 | 作業 | 完了条件 | 現状 |
| --- | --- | --- | --- |
| 0 | PC確認、専用Python環境、依存ライブラリとモデル取得 | import、モデルの出所・checksum、CPU/GPU状況を記録 | CPUで完了。GPU推論は未検証 |
| 1 | 人工配列でAbLang2を検証 | 10×480、有限値、繰り返しとbatch変更時の一致、保存・再読込 | CPUで完了 |
| 2 | 1人分3時点の入力検証とclone生成 | 時点・元行を追跡、除外理由を記録、科学的単位を確定 | 未着手 |
| 3 | AbLang2とK-means、スコア、Top N出力 | 独立に計算できる小例で式を検証し、実データで1人分を完走 | 未着手 |
| 4 | 共通UMAPと候補の可視化 | 3時点で軸・色の条件が一致し、候補表と強調表示が一致 | 未着手 |
| 5 | ローカルGUI | 3ファイル投入から進捗・候補数切替・保存まで操作可能 | 未着手 |
| 将来 | k-NN、複数人統合、QASAS用DB | 統合時の重複処理・来歴・QASAS入力形式を検証 | 今回の初期アプリ後 |

実データの処理時間は未測定です。完了日や全件処理の速度は、この10本の試験から保証しません。

## 次に決めること

1. Top Nを異なるCDR-H3配列数で数えるか、clone数で数えるか。**ユーザーの回答待ち**。
2. 元のLM-QASAS解析コード・AbLang2設定があるか。**ユーザーへ所在を確認中**。
3. Csegのisotype/subclass対応と、複数V候補・入力ラベル不一致の扱い。入力処理を実装する前に具体例を説明して相談。
4. 元コードが得られない場合のpooling、epsilon、K-means条件。根拠と暫定値を区別して決定。

質問への未回答を、合意として扱いません。Top Nの集約方法を変えても、embedding計算とclone観測の保持は分離します。

## 必要なものと現状

- Python、PyTorch、AbLang2：プロジェクト専用環境に導入済み。
- 学習済みモデル：公式Zenodoから取得・検証済み。外部APIの契約や認証キーは不要。
- CPU：今回の動作確認に使用。モデルを再学習する作業は不要で、学習済み重みを使う推論を行う。
- GPU：ハードウェアは検出済み。現ドライバーと新しいCUDA環境の互換性確認を別途行う。ドライバー変更はPC全体に影響するため、必要性と手順を具体化してから相談する。
- scikit-learn、UMAP、描画、GUI等：各段階で選定・導入・固定する。今回の最小検証には不要。
- 元論文のコード・設定：厳密な条件照合には有用。なくても環境構築は進められるが、同一条件の再現を宣言しない。

## 記録・原本保全

各段階でコード、条件、実行手順、検証結果、未確認事項をcommit/PRに記録します。実データの詳細と出力はGit管理外に置きます。原本を読み取る処理は書き込み処理と分離し、実データ実行時は前後のhash確認を残します。
