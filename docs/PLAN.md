# 開発計画

2026-09-20 更新。目標は、1人分のPre・Peak・Postを読み込み、解析の状況と画像を見ながら指定数の候補を抽出できるアプリです。

## 今回の区切り

入力検査、AbLang2、K-means、候補保存に加え、共通UMAPとローカルGUIを実装しました。CPM CSVに加え、対応するタカラ／RGレポートExcelの読込・実解析・画面操作を確認しました。日本語解説書で操作と判断の理由を追えます。動作確認の範囲と結果は開発記録へ残し、候補抽出の生物学的な性能検証と分けて扱います。

## 次に決めること

1. Top Nは異なるCDR-H3配列数で確定。300/500/1000または任意の正整数に対応。
2. 追加の修士論文を確認済み。最新論文・ポスターを優先し、元コード未提供のため厳密な条件一致は要確認。
3. 入力にはsubclass保持・allele除去・複数V/J注釈集合保持を暫定採用。[入力規則](INPUT_RULES.md)参照。
4. 公式seqcoding、epsilon=1、seed=20260919、n_init=10等で実装し、論文との厳密な一致は要確認として記録。
5. UMAP/KDEの表示設定は比較可能性を優先した暫定値。元論文との厳密な一致は要確認。今後は使用感を確認し、必要に応じてk-NNやQASAS用DBの入力形式へ進む。
6. Phase 6はRepertoire GenesisのHuman IGHレポート `hIGH20181210` の特定レイアウトに限定する。`Back_data!G:Q` の全データを読み、供給された `F` / `in-frame` の注釈を条件として使う。[Excel規則](TAKARA_INPUT.md)の境界と限界を維持し、残る全解析・画面操作の検証結果を開発記録へ追記する。

Top Nは合意済みです。他の事項は確定・暫定・要確認を区別します。ユーザーが委任した通常の実装判断は理由を記録して進め、結果の解釈を判断できない事項は確認します。embedding計算とclone観測の保持は分離します。

## 必要なものと現状

- Python、PyTorch、AbLang2：プロジェクト専用環境に導入済み。
- 学習済みモデル：公式Zenodoから取得・検証済み。外部APIの契約や認証キーは不要。
- CPU：今回の動作確認に使用。モデルを再学習する作業は不要で、学習済み重みを使う推論を行う。
- GPU：ハードウェアは検出済み。現ドライバーと新しいCUDA環境の互換性確認を別途行う。ドライバー変更はPC全体に影響するため、必要性と手順を具体化してから相談する。
- scikit-learn 1.9.1、umap-learn 0.5.12、matplotlib 3.11.2を導入・固定。GUIはPython標準ライブラリとローカルHTML/CSS/JavaScriptで構成する。
- 対応Excelの読込依存はopenpyxl 3.1.5、et_xmlfile 2.0.0、defusedxml 0.7.1に固定。Excelアプリ本体やCOM操作を使用しない。
- 元論文のコード・設定：厳密な条件照合には有用。なくても環境構築は進められるが、同一条件の再現を宣言しない。

## 図の相違を調べる次の方針（相談用の提案）

2026-09-20の方針相談に向けた提案。以下の比較実験を実施済み、またはすべて利用者と合意済みという意味ではない。論文5.4にisotypeが明記されていることと、原作図コード・粒度が未確認であることを分ける。[入力集合の確認](INPUT_SET_REVIEW.md)

1. **比較の基準を固定する。** 現在のD不使用、read数1の採用、V/J/CDR-H3/isotypeによるクローン整理を起点とする。最低read数とisotypeの実際の扱いは先方の回答を待つ。
2. **AbLang2の数値化を確認する。** 保存済み入力との対応、モデル・重み・平均する範囲を点検する。以前の限定的な確認を再利用し、未解決の点に絞る。別の平均方法を比較する場合は、入力集合とモデルを固定し、数値表現や近傍関係への影響を見る。
3. **UMAP、続いてKDEを確認する。** UMAPは同じembeddingで設定・乱数の影響を、KDEは同じ座標で平滑化や正規化の影響を切り分ける。変更する条件と判断基準を先に決め、画像の外形だけで条件を選ばない。赤点はこの段階に含めない。
4. **先方の回答を反映する。** isotype不使用が実作図の条件と確認された場合、まず採用行を固定し、クローン定義からisotypeだけを外す比較を行う案とする。C注釈による行の採否変更は別の比較とし、同時に変えない。論文記載との差も記録する。

実装が意図どおり動くことと、共同研究者の原図を同じ条件で再現したことは別に判定する。元条件が不明な間は、原法との一致を断定しない。各段階で確認できたことと未解決点を報告し、条件を標準運用へ取り込むかはその根拠とともに整理する。
