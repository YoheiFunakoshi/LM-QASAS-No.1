# 作業手順と再開方法

## 再開時

1. README、GUIDE_JA、SPECIFICATION、DECISIONS、DEVELOPMENT_LOGを読み、現在地と未決定事項を確認する。
2. `git status --short --branch`、`git remote -v`、`git log -5 --oneline`で実際のGit状態を確認する。記録だけで同期済みと判断しない。
3. 必要ならローカルの`local_records/`を参照する。内容は公開GitHubや会話に無条件で貼り付けない。
4. 段階に必要な仕様のみ相談し、合意済みの事項を繰り返し質問しない。

## ディレクトリの役割

- リポジトリ直下・`docs/`: 公開可能なコード管理情報、仕様、手順、判断、開発履歴。
- ユーザー提供の「LM-QASAS No.1 データ」「LM-QASAS No.1 資料」: 原本。削除・上書き・改変しない。
- `local_records/`: 実データの監査、ファイルhash、具体的な検証結果など。Git管理外。
- `outputs/`: CLIで作成する実解析結果。runごとに別の保存先を作り、以前の結果を上書きしない。
- `app/`: ローカル操作画面。`Start-LMQASAS.cmd`から専用Pythonで起動する。
- `local_records/ui_inputs/`、`local_records/ui_jobs/`: GUIで選んだCSVのコピー、元ファイル名・hash、jobの進捗。すべてGit管理外。
- `models/`、仮想環境、キャッシュ: ローカルのみ。モデルの識別情報と取得手順を公開可能な文書に記録する。

.gitignoreは、プロジェクト直下で登録を許す場所を限定し、さらにデータ形式・出力・秘密情報を除外する。将来の模擬fixtureや画像を登録する際は、内容を確認して具体的な例外を追加する。ignoreは暗号化や送信防止機能ではなく、強制addや既に追跡済みのファイルには別途確認が必要。

## 作業中

- 原本を開く場合は読み取りのみ。filterや正規化は解析用データに適用し、変更内容を記録する。
- 実データの検証前後には必要に応じてSHA-256を比較し、ローカルに監査記録を残す。
- Google Driveは現在の指示では利用しない。
- 実配列や被験者情報をツールの標準出力へ流さない。確認に必要な集計も公開記録とローカル記録を分ける。
- 科学的な定義を変更した場合は、論文由来の設定と実装上の変更を分ける。
- テストは変更に応じて実施し、未実施・未確認を成功と記載しない。

## Gitに記録するとき

1. 通常の開発では`codex/`で始まる作業branchを使う。
2. ファイル名を明示してstageする。研究データを含み得る作業先で、無確認の一括addや強制addをしない。
3. `git diff --cached --name-only`と`git diff --cached`で登録内容を確認する。
4. `git ls-files`で研究データ・提供資料・出力が含まれていないことを確認する。ignoreがあることだけで判断しない。
5. 変更理由と検証結果を文書に追記し、意味のある単位でcommitする。
6. GitHubへ反映したら、remoteのcommitと登録ファイルを確認する。PRを使う変更ではそのリンクを残す。

空のリポジトリに対する今回の記録基盤のみ初期化としてmainに登録する。今後の機能開発は変更を確認できるbranch/PRで進める。

## 完了報告

作業範囲、確認した検証結果、未完了事項、GitHub上のbranch/commit/PR、ローカルとの同期状態、原本への変更有無を短く報告する。

## 機能の進捗を判定する基準

- 文書があることは機能が実装済みであることを意味しない。
- packageがimportできるだけではembedding成功とはしない。
- 模擬データの成功を実データの成功としない。
- 出力があるだけでは論文と同じ方法・結果を再現したとはしない。
- 候補数、観測単位、filter、モデル・設定、出力への由来が追跡できる状態を目標とする。

## 解説書をコードと一緒に維持する

引数・入力規則・出力名・既定値が変わった場合はGUIDE_JAとINPUT_RULESも更新する。実行可能な説明例とコードを照合し、テスト成功、実データ完走、生物学的検証を区別する。過去の実行結果には解析時点のコードhashを保存し、新しい実装結果と混同しない。

GUIや図を変えた場合はVISUALIZATIONも同期し、候補表・印・保存画像が同じselectionを参照することを検査する。研究画像を公開の画面例として登録しない。小さな模擬データで新規解析の操作を、実データの保存runで再利用を検証した場合は、その範囲を明記する。
